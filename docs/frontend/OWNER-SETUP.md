# Owner setup, funding and activation

The frontend does not broadcast owner transactions. Use the Founder setup screen to simulate and download unsigned JSON, or inspect the concrete public-chain transaction data in [live-chain.json](evidence/live-chain.json). Re-simulate each step after the preceding transactions are confirmed. An unsigned file is not a signed transaction and cannot move funds by itself.

The verified owner is `0x48E4E74fE1d0c14404cEB57B9fec5b21329C6ec9` on Ethereum chain 1. The token and hook addresses come from the runtime deployment manifest. At the recorded observation the pool is initialized, the hook is bound, price references are valid and trading is closed. Migration backing is zero; router support and the native swarm distributor are unset.

1. **Fund the immutable vault.** The live hook reports `0xCf52776A56f0b6d326DB9F1Da7abD4Dad7BD711F` as MigrationVault. Transfer the actual deficit from the owner: currently **700,000,000 UNLK2**, in 18-decimal base units `700000000000000000000000000`. This is the reserve portion of the founder's 750m factory remainder. The final 50m is the founder allocation. There is no approval step for a direct token transfer. Vault principal cannot be recovered. Verify `remainingBacking() >= remainingCapacity()` and `isFullyFunded()` after confirmation.
2. **Register the configured Universal Router.** Use the address from `network.uniswapV4.universalRouter` and `setRouter(router, true)`. Its `msgSender()` view was callable during read-only verification. Register only a compatible router: arbitrary contracts can lie about the trader, and unregistered contracts share all users' rights. Do not register the configured quoter: its deployed `msgSender()` call reverted. Sell quotes can instead use the interface's custom-minimum path and final router simulation.
3. **Set the actual native swarm MerkleDistributor.** Enter the real address from the launch record in the owner setting. No substitute is provided. The app checks code and the `merkleRoot()` / `isClaimed(index)` interface; the owner must verify that the tree belongs to this launch and uses the accepted Uniswap leaf format `keccak256(abi.encodePacked(index, account, amount))`. Download `setSwarmDistributor(actualDistributor)` from the screen. There is intentionally no prefilled distributor transaction in the evidence: its address is owner-settable and is not supplied by the handoff.
4. **Inspect liquidity and all prerequisites.** Confirm initialized official PoolKey, correct chain, token/hook binding, remaining backing, pricing references, registered Universal Router and configured distributor. Liquidity can be added before activation; after activation only the factory can add to the official pool. Removals remain possible. No liquidity action is fabricated by this interface.
5. **Activate and seal once.** `activate()` is included as concrete unsigned calldata in the evidence. Its current `eth_call` simulation fails because funding is incomplete. After setup, refresh and use the owner screen to obtain a fresh simulation and unsigned transaction. Activation is permanent, has no 48-hour delay and disables every setter forever. The interface requires router and distributor setup even though the contract's activate method does not enforce those two settings. There is no configuration recovery after sealing.

Allocation conservation: 150m pool + 100m native swarm + 700m migration + 50m founder = 1,000m minted once. Founder sell rights are exactly 50m, reduced by applicable earlier uncredited burns; the 750m remainder is not all founder eligibility. Migration already completed would reduce remaining capacity, so always fund the actual remaining deficit rather than reusing an old amount blindly.

Migration is first come, first served, 1:1, with a lifetime 700m cap that cannot cover all V1. V1 locks irreversibly. Contributions burn only for the collecting gate and reject changed gates or excessive amounts; voluntary burns earn points without moving gates. Both burn paths debit origin credits conservatively. Rewards are not a fixed return and future burns dilute future point shares.

Funding and router setup simulations in the evidence succeeded as `eth_call` at observation time. They were never signed or broadcast. Owner state can change; the evidence is a dated snapshot, not execution authorization or a promise that a later transaction will succeed. Publication, site naming and IPFS pinning follow source delivery and are outside this worker's actions.
